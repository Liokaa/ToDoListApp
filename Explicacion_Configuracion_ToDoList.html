Documentación Técnica: Configuración y Personalización

Aplicación ToDoList • Arquitectura, DataStore, Temas e Internacionalización

Resumen Ejecutivo: Este documento explica de forma concisa la arquitectura interna de la pantalla de Configuración (InterfazConfig), el uso de DataStore Preferences para la persistencia reactiva, el sistema de Temas Claro/Oscuro y el mecanismo de Multi-Idioma mediante archivos de recursos strings.xml.

1. Arquitectura de InterfazConfig y Librerías Utilizadas

La actividad InterfazConfig centraliza las preferencias de personalización de la aplicación. Se conecta directamente con el gestor de datos SettingsDataStore y notifica los cambios al sistema Android en tiempo real.

Librerías Críticas y Dependencias:

Librería / Modulo Nombre del Paquete Función y Propósito en la App
DataStore Preferences androidx.datastore:datastore-preferences Almacenamiento asíncrono y reactivo de preferencias (Tema, Notificaciones, Idioma).
AppCompat androidx.appcompat:appcompat Gestión dinámica de temas con AppCompatDelegate e idiomas con LocaleListCompat.
Material Components com.google.android.material:material Componentes visuales estilo Material 3 (SwitchMaterial, RadioGroup, Button).
Kotlin Coroutines & Flow org.jetbrains.kotlinx:kotlinx-coroutines-core Lectura/escritura asíncrona sin bloquear el hilo principal (UI Thread).

Conexiones con otras Interfaces:

  • Navegación desde Perfil de Usuario: Se accede a través del botón de ajustes con el icono de engranaje (@drawable/ic_config_gear) presente en InterfazUsuario.
  • Aplicación Global al Iniciar: En InterfazCarga.kt (Splash screen), se leen las preferencias guardadas en DataStore para establecer el tema y el idioma globales antes de cargar cualquier otra interfaz.

2. Funcionamiento de DataStore Preferences

DataStore Preferences es la solución moderna de Android Jetpack para guardar pares clave-valor de forma asíncrona, segura y consistente, reemplazando a la antigua API SharedPreferences.

Estructura en la App (SettingsDataStore.kt):

  • Instanciación: val Context.dataStore by preferencesDataStore(name = "user_settings")
  • Claves de Preferencia:
    • KEY_DARK_MODE (booleanPreferencesKey("dark_mode")): true para Modo Oscuro, false para Modo Claro.
    • KEY_NOTIFICATIONS (booleanPreferencesKey("notifications_enabled")): true / false para notificaciones.
    • KEY_LANGUAGE (stringPreferencesKey("app_language")): Códigos ISO "es", "en", "ja".
  • Lectura Reactiva (Flow): Los datos se exponen como flujos de datos (Flow<T>) que emiten valores actualizados de manera automática.
  • Escritura Asíncrona (Corrutinas): Se usa context.dataStore.edit { ... } dentro de bloques lifecycleScope.launch.

3. Implementación del Modo Claro y Modo Oscuro

El sistema de temas se basa en la combinación de AppCompatDelegate y archivos de colores adaptativos según la configuración de noche del sistema.

Ajuste Dinámico del Tema:

val targetMode = if (isDark) AppCompatDelegate.MODE_NIGHT_YES else AppCompatDelegate.MODE_NIGHT_NO
if (AppCompatDelegate.getDefaultNightMode() != targetMode) {
    AppCompatDelegate.setDefaultNightMode(targetMode)
}

Recursos de Color Adaptativos:

  • Modo Claro (res/values/colors.xml):
    • Fondo principal (app_bg): #FAF6E8 (Crema pastel suave).
    • Fondo de tarjetas (card_bg): #FFFFFF (Blanco puro).
    • Texto principal (text_main): #2A242B (Gris oscuro/negro).
  • Modo Oscuro (res/values-night/colors.xml):
    • Fondo principal (app_bg): #121212 (Gris oscuro mate mate sin reflejos).
    • Fondo de tarjetas (card_bg): #1E1E1E (Gris contenedor oscuro).
    • Texto principal (text_main): #E2E8F0 (Blanco suave para evitar fatiga visual).

Control Anti-Bucle de Recreación: Se verifica getDefaultNightMode() != targetMode antes de invocar el cambio de tema para evitar que Android reinicie la actividad de forma infinita en cada inicio.

4. Multi-Idioma y Funcionamiento de Recursos strings.xml

Android implementa el estándar internacional i18n mediante el desacoplamiento de cadenas del código fuente. Las cadenas no se escriben directamente en Kotlin ni en el XML, sino que se referencian por clave (ej. @string/config_title).

Estructura de Calificadores de Recursos:

Idioma Ubicación del Archivo Ejemplo de Clave y Traducción
Español (Base) res/values/strings.xml <string name="config_title">Configuración</string>
Inglés res/values-en/strings.xml <string name="config_title">Settings</string>
Japonés res/values-ja/strings.xml <string name="config_title">設定</string>

¿Por qué funcionan como una traducción automática?

  1. Cuando la app cambia de idioma con AppCompatDelegate.setApplicationLocales(LocaleListCompat.forLanguageTags("en")), el motor de Android reemplaza dinámicamente las referencias @string/clave por el texto correspondiente de la carpeta values-en.
  2. En el código Kotlin, el método getString(R.string.clave) lee automáticamente la traducción correspondiente según el Locale activo en ese instante.

5. Puntos Críticos e Importantes de la Configuración

  • Botón Restablecer Ajustes (btnResetConfig): Permite retornar la aplicación a sus valores de fábrica (Modo Claro, Notificaciones Desactivadas, Idioma Español) con un solo toque, sobrescribiendo DataStore y refrescando la UI.
  • Notificaciones Programadas (NotificationScheduler):
    • Recordatorio por defecto: 1 día antes a las 9:00 AM usando AlarmManager.
    • Recordatorios personalizados: Permite al usuario seleccionar fecha y hora con TimePickerDialog.
    • Compatibilidad Android 12+/13+: Verificación previa con canScheduleExactAlarms() y permiso POST_NOTIFICATIONS para evitar fallos de seguridad (SecurityException).
  • Legibilidad en Tarjetas de Papelera: Los textos en item_papelera.xml usan tonos oscuros fijos para asegurar visibilidad óptima sobre la tarjeta blanca, evitando texto blanco sobre blanco en Modo Oscuro.
